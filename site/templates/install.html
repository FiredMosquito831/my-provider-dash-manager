Two install routes

Pick one. They end in the same place.

The command-line route downloads the newest installer from GitHub, verifies it is a real Windows executable, runs it, and launches the app.

OPTION A · RECOMMENDEDnpx

From the command line

Requires Node.js 18 or newer.

$ npx my-provider-dash-manager

Run the same command later to update. The package also installs the short alias mpdm when installed globally.

OPTION B · DIRECT.EXE

Download the installer

No Node.js needed. Download My-Provider-Dash-Manager-Setup-{{ version }}.exe from the latest release and run it.

Open GitHub Releases →

The installer installs per user under %LOCALAPPDATA%\Programs and creates Start Menu and Desktop shortcuts.

SmartScreen will warn on the first run. The installer is not code-signed yet. Choose More info → Run anyway. Code signing is planned and removes the warning.

First run

Three steps to a usable rail.

  1. 01

    Add an account

    Click Add account at the bottom of the rail, choose a service from the searchable picker, name the account, then choose Log in or Create a new account.

  2. 02

    Sign in inside the session

    The real sign-in page opens in that account's own isolated session. Google services sign in directly. Elsewhere, prefer email/password or GitHub over “Continue with Google”.

  3. 03

    Repeat, then switch

    Add every identity you need. Click a rail row or a tab to switch. Everything stays signed in. Optionally connect read-only tokens or import saved passwords.

Keep it current

Three routes to the same update.

Automatic, in the app

Default. Checks on startup and hourly; downloads in the background; installs silently on close or on Restart & update. The rail badge turns into Restart to update x.y.z when it is ready.

From the command line

npx my-provider-dash-manager — or mpdm update — updates an existing install silently and in place. Add --interactive for the wizard. Close the app first, or the running copy keeps the old version until restart.

From the release page

Run the newest installer. It upgrades in place. Accounts, sessions, saved logins and settings live in %APPDATA%\multi-acc-manager and survive updates and reinstalls.

The CLI

A small lifecycle tool, not a second app.

Install globally with npm i -g my-provider-dash-manager to use the package name or the shorter mpdm alias anywhere.

CommandWhat it does
my-provider-dash-managerInstall or update to the newest release, then launch
… install / … updateInstall or update only
… startLaunch the installed app
… statusInstalled version vs latest, plus where the app and your data live
… wherePrint the install and data paths
… uninstallRun the uninstaller (accounts and sessions are kept)

Flags: --silent (no wizard on a first install), --interactive (wizard for an update), --download-only, --force, --version, --help. From a checkout of the repository, the equivalent is npm run install:latest.

Where things live

Requirements and paths.

Windows only, for now

Windows 10 or 11 (64-bit). macOS and Linux are not supported yet. The architecture is cross-platform, so other operating systems remain future work.

Memory

About 350 MB with all tabs asleep, plus roughly 125 MB per live dashboard and about 2 MB per open account when dark mode is on. Eight GB of RAM handles the default five warm tabs comfortably.

Install path

The app installs per user under %LOCALAPPDATA%\Programs. Updates install in place.

Data path

Accounts, sessions, settings, plugins and encrypted logins live in %APPDATA%\multi-acc-manager. They survive updates and reinstalls.

No account, no server

The app is local-first: no telemetry, no sign-in to a service of ours, no cloud sync. The repository is public, so update checks need no token.

Run from source

Developers can npm install then npm start. Smoke suites and release tooling are documented in the repository README.

If something sticks

The two known escape hatches.

SmartScreen on first run

Expected while the installer is unsigned. Choose More info → Run anyway. This is not a malware report; it is the absence of a signing certificate.

A dashboard will not load

Google Cloud Console is a known case. Use the Browser button in the strip to open that page in your system browser. The rest of the app is unaffected.
