The problem

Every provider assumes you have one identity.

Freelancers, agencies and developers carry a personal account, a client account, a work account — often on the same service. The browser was never built for that.

WITHOUT ISOLATION
  • ×Signing out of one account to reach another, then signing back in again.
  • ×Juggling browser profiles, one window each, with no single place to see every account.
  • ×Asking “which account am I actually in right now?” before changing anything.
  • ×Losing your workspace on restart, or re-typing the fifth account's password.
  • ×Ads, blinding white dashboards, and a different extension setup per profile.
WITH PROVIDER DASH
  • ✓Every account stays signed in, in its own storage partition.
  • ✓One window: providers in the left rail, open accounts as tabs on top.
  • ✓Every tab and rail row is colour-coded and labelled by account.
  • ✓The open-tab set is remembered and restored on the next launch.
  • ✓Built-in ad-blocking and dark mode, plus saved logins bound to each account.

It is not a browser and not a scraper. It is a container for identities: real dashboards, real sessions, one place.

Security posture, honestly

Local-first. Encrypted at rest. Explicit about the limits.

Cookies, tokens and saved passwords are encrypted with Windows DPAPI. Saved logins are bound to the account and the service's own origins. There is no server, no app account and no telemetry. DPAPI does not protect against malware running as you — no desktop app can — and the installer is not code-signed yet. The site says so on the security page instead of hiding it.

Read the security model →

  • ✓Origin-bound credential capture and fill
  • ✓Sandboxed account views, context isolation, deny-by-default permissions
  • ✓No sync and no telemetry — state stays on this machine

From install to signed in

Three steps, no setup wizard.

  1. 01

    Add an account

    Click Add account at the bottom of the rail, choose a service, name the account, then log in or create one. The real sign-in page opens inside that account's own isolated session.

  2. 02

    Sign in normally

    Google services sign in directly. On other sites, prefer email/password or GitHub over “Continue with Google”, which Google blocks in embedded browsers. The Browser button finishes stubborn flows in your system browser.

  3. 03

    Switch and stay signed in

    Click a tab or a rail row. Everything stays warm and signed in. Optionally connect a read-only API token for a status card, or import passwords from your browser.
